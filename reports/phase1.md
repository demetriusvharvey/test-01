# Phase 1: source history and ingestion

## What is shipped

- The existing pipeline is separated into ingestion, features, model, market, ledger, report and runner components. `scripts/pipeline.py` remains a compatible entry point. Existing pick IDs, frozen sides, recorded prices and grades are preserved.
- The hourly workflow writes date-partitioned SQLite observations to the `data/observations` branch. Rows include both sides, the provider, book, event, provider timestamp, actual fetch time and scheduled start; append-only triggers block UPDATE and DELETE. No quote received after start, lacking a side or timezone, stale by more than 95 minutes, or dated in the future is accepted. A separate close table freezes the last recorded pregame quote only when a matching ESPN start is available and consistent. It is explicitly labeled a proxy, with source age and fetch-to-start gap; it is **not a certified or sharp closing line**. Postponements, low collection frequency, missing games and schedule changes can leave no reliable close.
- Provider-level duplicate conflicts and material disagreements are quarantined before selection; start times must match ESPN within 20 minutes. At least three remaining books are still required. A missing or failed observations store suppresses new predictions. Gap detection flags a delay between successful runs, but GitHub's scheduler has no guaranteed delivery window.
- The Odds API adapter is enabled only when `ODDS_API_KEY` exists, at most once per six hours per league, with a hard 240-request monthly ceiling and a provider-quota reserve. Its free tier may not include every book. It never logs key-bearing URLs. The existing twice-daily optional FanDuel feed also uses the same key and quota. AgentBets states that its prices come from The Odds API: comparing the two can flag differences but does **not** constitute independent-source confirmation. Without a key there is no second source/fallback.
- A separate backfill workflow is configured to snapshot the entire nflverse `games.csv` and 2021–2026 play-by-play, injury, depth-chart and snap-count files, plus BoxScore Lab team-game box scores for 2022-23 through 2026-27. SQLite source shards retain every CSV column, original content (gzip-compressed if needed), SHA-256, retrieval time, URL and attribution. Every asset is marked `retrospective_only`; historical revisions, inactives and status changes are not assumed known before a pick. The current seasons are partial. A successful workflow run is needed to verify actual coverage. Run `python scripts/backfill.py` with `PICKS_DATA_ROOT` pointing to the research checkout or dispatch the GitHub Actions backfill workflow.
- NBA assignment snapshots retain their first *observed* timestamps and later changes. Public first-publication times, historical game-level officiating, detailed injuries/inactives, player-level NBA box scores beyond the available source, and venue-based travel are not backfilled: a usable licensed, timestamped source has not been established. NBA historical prices are not backfilled. NFL schedule moneylines are preserved only as retrospective source fields; their book and timing are not certified as closes.
- The previous rest and five-game margin promotion was exploratory. Those candidate features are disabled and no longer tested every production run; the old ledger is unchanged. An untouched future confirmation and the other preregistration/replication gates are still required. The baseline remains experimental and not validated as profitable.

## Storage and timing tradeoffs

Daily SQLite shards keep hourly writes away from the source/production branch and prevent an ever-growing monolithic database from being recommitted each run. The data branch is in the existing repository and inherits its visibility; source data and permitted use are documented in `DATA_SOURCES.md`. Backfill adds sizeable source files once and should be rerun deliberately; repeated revised vintages increase repository size. It does not pretend a Git branch is infinite storage. A live data store, scalable compaction and backup policies remain future engineering work.

No extra pre-tip polling is enabled: AgentBets publishes hourly snapshots, so more frequent polling cannot make its upstream quote timestamp fresher, while GitHub cron can be delayed and the optional API's free allowance is limited. More frequent polling can be revisited with a permitted source, quota and evidence of benefit. The browser refresh interval is not the data-source update interval.

## Research results

No new hypothesis test, p-value, ROI or CLV estimate is claimed in this phase. The two previously used seasons were already examined and cannot be relabeled an untouched holdout. `HYPOTHESES.md` defines future tests; logs, multiple-testing adjustment, multi-season replication and an untouched confirmation are not yet implemented. Referee effects require partial pooling and separate qualified research.
